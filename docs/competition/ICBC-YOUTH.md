# 工行杯 · 青年群体服务方案

## 作品概要

**青财：从银行账单到生活目标的安全理财助手。** 面向在校学生、初入职场和收入波动的青年用户，提供可以核对的现金流、资金预留、目标规划和银行操作体验。保留简洁的 Liquid Glass 风格，入口采用首页、账本、图表、助手、投资五个主导航。

官方将青年群体服务列为参赛方向，强调从真实需求出发形成创新、可行的服务方案；本方案以此组织需求和演示。没有开展真实用户访谈或满意度统计，以下痛点是产品假设，不能伪装成调研结论。[工行大赛介绍](https://www.gonghangbei.com/dsjs.html)

## 青年需求与服务

| 产品假设 | 可交互服务 | 评价方式 |
|---|---|---|
| 学费、生活费与投资计划分散 | 选择学生阶段，先预留学费与应急金，再比较方案 | 近期目标不被误算为可投资资金 |
| 第一份工资后不清楚租房押金、固定开销和长期安排 | 导入流水→校分类→个人计划→目标每月需求 | 导入前后账本和建议同源、目标可解释 |
| 副业或自由职业收入波动 | 展示覆盖月份与稳定性，不从短期数据推断长期能力 | 仅有工资、未核对完整性或结余不足时不给长期额度 |
| 对 AI 操作资金有疑虑 | 对话只生成草稿；显示完整对象、金额；敏感操作动态验证 | 未确认不动钱、重复点击不多扣、未知结果能核账 |
| 愿意纠正助手但担心数据被收集 | 默认关闭的结构化反馈和逐条审核 | 不保留原话、精确金额或身份；能退出 |

## 示例服务旅程

以虚构初入职场青年为例：导入三个月完整合成流水，检查餐饮/住房分类，排除本人内部划转；核对生活开销与未计入账单的还款，确认收支完整后选定租房押金目标和用款期限。助手读取汇总，不读取账户号，先说明覆盖、应急金和目标压力，再提供调整计划或方案比较入口。用户选择灵活现金或符合条件的长期方案，输入模拟申购本金，核对参数后得到持久回执。提现回到现金，不计为收入。

同一目标在图表、个人计划和投资中保持一致，首页进入同一份资金安排。更换目标明确选择保留或归零，期限比较只测算不改计划。目标进度与体验银行资产各有明确来源，不能把“计划存下”直接展示成“实际赚到”。

## 创新与可行性

创新重点是连贯的服务流程：把生活阶段、现金流、目标和独立执行保护连接起来；让模型解释事实、让用户控制资金、让经审核的结构化修正进入下一轮训练。没有宣称新型基础模型、新密码算法或盈利策略。

原记账/投研服务保持，接口代理统一同源；本地轻量 LoRA 可复现，基础记账无需 GPU。比赛演示使用模拟银行，所有投资本金真实持久化但没有真实风险敞口。安全采用用户提供的 MIT 内核，补齐网页会话、参数核对、动态码、恢复和审计展示。

## 三人分工建议与后续验证

团队人数已确认三人；姓名、学校和队长由团队填写，不代造信息。可按产品与交互、数据与模型、安全与工程分工；共同参加场景验收和材料核对。

下一阶段真实验证计划：招募自愿参与的在校与毕业青年，先用示例记录完成任务，测量操作完成率、追问轮次、分类修正和误操作；访谈验证预留金额是否易懂。未开展前，不在材料中填写效果百分比或用户规模。

商业/银行接入路径：在正式身份、用途授权、TLS、真实产品适当性与银行对账接口完善后，作为青年手机银行的“账单到目标”服务入口。当前版本不出售金融产品、不承诺收益。
