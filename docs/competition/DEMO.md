# FinPilot演示脚本

## 8 分钟答辩

| 时间 | 演示 | 讲述要点 |
|---|---|---|
| 0:00–0:40 | 首页 | 财富管理的难点是哪些钱可用、何时要用、能承担什么风险；FinPilot 把依据和操作连起来 |
| 0:40–1:30 | CSV 预览→改分类→确认 | 先校正再入账；重复导入不重复添加；内部划转不制造收入 |
| 1:30–2:40 | 图表与资金规划 | 同一账本范围；开销、还款与完整性核对；应急金目标和实际已留金额分开；只有工资不开放长期 |
| 2:40–3:40 | 目标与规划助手 | 所选区间数字一致；目标剩余 9,000 元，12→6 个月只测算 750→1,500 元；看清期限压力 |
| 3:40–4:50 | 方案比较 | 对照两种模拟方案的风险、用途、期限、赎回和费用；说明不适合原因，不能把模拟规则冒充真实产品 |
| 4:50–5:30 | 历史投资研究 | 核对来源日期；异常行情不用于价格图；报告只引用已核对事实 |
| 5:30–6:20 | 模拟申购／赎回→确认→结果 | 本金、现金与模拟总资产一致；草稿不扣款、用户核对参数、重复点击不重复执行 |
| 6:20–6:55 | 模型与操作保护 | 历史模型评估、当前回归分别列示；模型没有资金权限，敏感操作使用动态码 |
| 6:55–7:25 | 结构化反馈 | 自愿参与、默认关闭、逐条审核、离线评估；没有真实用户成果数据 |
| 7:25–8:00 | 方向适配与下一步 | 已有个人资金管理流程；补强按需术语解释、存量资产负债和用户理解验证，不声称完整智能投顾已上线 |

演示用独立示例账本和银行状态；不要在用户实际账本注入测试流水或公开二维码、入口凭据。开场明确“体验账户”，状态标签保持可见。某个接口不可用时演示错误状态，不用截图冒充实际执行。

## 4 分钟可选视频

0:00 资金与风险痛点；0:30 流水与规划；1:10 目标期限测算；1:50 风险／期限／费用比较；2:35 模拟申购与回执；3:15 历史研究与模型依据；3:40 已有能力与待补强项。用同一网站、同一 UI 风格，避免堆叠技术小字。

视频不是必交材料，本轮提供可复用脚本。提交前如录制视频，实际时长控制在五分钟以内，公开前检查没有真实身份、密钥或访问地址凭据。

## 答辩问题准备

- “为什么选择财富管理服务？”核心是个人资金用途、目标和风险约束，以及看懂方案依据；青年只是可以先验证的用户群。具体对照见 ICBC-WEALTH.md。
- “已经能做全资产配置吗？”还不能。目前有现金流规划与两种模拟方案，存量资产负债、多资产配置和真实产品适当性属于后续工作。
- “为什么模型不能直接转账？”模型负责理解和解释；用户独立确认完整参数，控制平面再核验身份、来源、新鲜事实和义务。这是实际代码边界。
- “个性化体现在何处？”用户阶段、固定开销、现金流覆盖、目标压力和风险偏好改变原因、产品资格及金额上限；不是向所有人推荐同一个收益承诺。
- “飞轮用过真实用户数据吗？”没有。已经跑通一条隔离开发者反馈，模型主要使用人工编写合成数据；真实用户数量为零。
- “是不是安全包原有成果？”内核来自用户提供的 MIT 包；本轮新增网页会话、动态码、用户事件绑定、资金/计划逻辑和错误恢复集成。
- “如何证明效果？”列出报告中的固定测试、实际模型调用、浏览器任务和故障样例；不以单一测试数量代替广义安全或真实收益结论。

## 评委可现场复核的纠错流程

1. 文字解析输入“今天午饭35元，打车18元，帮我记两笔。”：明确要求逐笔核对，没有部分草稿或账本写入。
2. 保存一笔午餐，再从详情改金额：ID 不变，统计同步；筛选餐饮后可见分类小计。
3. 旅行目标 12,000 元记录 3,000 元后改成电脑 3,000 元：出现保留/新建选择，新建为零进度；进度记录可撤销。
4. 从规划展开计算依据进入账本：顶部显示六个月实际区间。返回首页选9月，“问助手”仍核对9月。
5. 仅导入三个月工资并填写高风险偏好：长期均衡仍不可申购。补全开销、还款和完整性确认后重新评估。
6. 查看招商银行历史研究：异常行情不画价格图；报告不虚构成交额。查看长江电力可用行情，对照来源日期。

以上使用独立验收状态。没有启用图片识别，也没有将批量自然语言输入做成自动入账；答辩不要声称这两项已实现。
